# 演示手册 · 2026-09-22

给「明天要演示现在的原型」准备的：一套能上传的材料、一条 15 分钟的路、每一步该看见什么、以及跟另一个组（beta5）版本的差异点。
起预览：`npm run dev` → http://localhost:3000 。材料在 `materials/`，重新生成用 `python make-materials.py`。

## 材料（materials/）

原型里的解析是 **mock**：按文件种类走固定剧本，不读内容。所以这五份文件的作用是"演示时看着像真的"——名字是真实项目的命名习惯，打开有内容，跟剧本对得上。

| 文件 | 演示时当什么用 | 上传后原型做什么 |
|---|---|---|
| `BB-001_食蟹猴28天DRF毒理试验方案_v2.0_20260915.docx` | **主材料**，客户方案 | 读成 BB-001 方案：7 组 / 37 采样事件 / 7 分析方法，识别 11 项、2 项待确认、6 项无价目，账 27 行 5 板块 |
| `给药分组表_方案截图_20260919.png` | 客户在微信里转发的表格截图 | OCR 剧本：7 行 × 5 列，识别 3 项、1 项待确认（多模态入口） |
| `微信沟通记录_XX药业_BB-001报价_20260918.txt` | 客户群聊导出 | 聊天剧本：区域 / 语言 / 格式 / 交付时间，其中「周三前给初版」没有格子 |
| `BB-001_采样计划与分析物清单_20260916.xlsx` | 配套清单 | 同方案剧本（mock 按种类走）。演示里当第二份材料传，讲"两份来源都读到同一项时人确认过的不退回" |
| `往期报价_TK-2039_XX药业_20260612.pdf` | 往期报价道具 | 同方案剧本。只在讲「材料种类」时露一下，别当主材料传 |

**规则**：文件先说话——方案和一句话同时发，方案为准；只有本地上传的才算材料，工单附件不读；退回会话不读任何材料。

## 15 分钟的路

**0. 空间首页（1 分钟）** — 侧栏点「XX药业-PD1临床前评价」行 hover 的 ↗ 进空间首页。
看：空间插画 + 标签、四张专家卡（hover 一张，介绍卡从卡底长出来：做什么 / 几步 / 交出什么）、右上「配置专家」、底部概览三张卡。
说：beta5 把项目改成了空间、每个空间一个入口页——我们只改了名字和这一页，会话层没动。

**1. 一句话开始（1 分钟）** — 点「DMPK 报价」卡。输入框打：
`PK 小分子，SD 大鼠，每组 6 只，3 组，试验周期 2 周，血浆，中文报告`
看：右栏自动切到「报价板块」——动物使用两行已计价（¥5,940），采血 / 检测 / 报告标「缺参数 · 去填」。
说：账不等参数齐才有，填一项亮一行；这就是会上说的"右栏只做参数状态 + 单价"。

**2. 传方案（3 分钟）** — 点「+ › 添加文件 › 本地文件」，选 `BB-001…方案_v2.0.docx`，发送。
看：对话里的解析轨迹（7 步，点「查看过程」展开，每步有"读出了什么 / 原文在哪"）；一句话汇报「已识别 11 项、2 项待确认、6 项无价目；已计价 21 项 ¥580,360」；正文里列出还缺的 3 项。
右栏停在「参数收集」：文件认出来的标「识别」，铅笔逐项确认，或顶部「确认全部」。点任一行的来源标记 → 原文句子 + 锚点（P0-1 原文依据）。
说：文件为准，机器读出来的是**提议**，人点过头的才是参数。

**3. 板块（2 分钟）** — 切「报价板块」tab。
看：5 个板块，默认只开第一个有待定项的；段头有几项 / 几待定 / 小计；行是「名字 + 数量 × 单价」，下一行待测物 · 方法；点段头折叠 / 展开。
底部尾卡：合计 ¥580,360、本单规则两枚胶囊、两扇门。
说：来源、公式、规则都不在这儿（在「报价明细」「输入材料」tab），这一栏只回答"收了什么、多少钱"。

**4. 临时改价（2 分钟）** — 展开「动物使用」，点「食蟹猴使用费」单价旁的铅笔。
看：原价 ¥32,500 · 价目 v1.0.13 → 输入 30000 → 确认。行上变成 ¥30,000 + 「临时价 · 原 ¥32,500 · 恢复」，对话里一句「已按临时价记账，仅本次报价，价目表不动」，小计和合计跟着变。
再展开 TOX，点「细胞因子检测」的「补价」：系统无价目 · 本单补价 → 200 → 确认。
说：改价是临时调价的唯一路径（会议共识 1）；无价目不按零元，人补一个只作用于本单。

**5. 问价目（1 分钟）** — 尾卡点「在对话里列出本单价目」→ 那句话落到输入框，自己按发送。
看：数字同事回一张表：费用项目 / 板块 / 单价 / 本单用量 / 状态，临时价带原价，无价目另起。
再点「查看完整价目表 ↗」→ 报价管理 · 标准价格，页首一行"这是全局价目表……"；点「返回工作台」→ 会话原样还在。
说：完整价目表不进对话（共识 2），本单命中的那一截可以问；后台是独立入口。

**6. 生成 → 交接 → 复核（3 分钟）** — 补齐参数（输入框一句 `每组 2 只，LC-MS/MS，国内`，或展开参数卡点选），「确认并生成报价单」→ 产物两张卡，预览 Excel 内部计算表 / Word 报价书（纸面就是这份账）。交接卡交给王林彬。
切账号到王林彬 → 站内信 → 工单 → 开始审核 → 「计算表」tab → 批注 → 退回修订。
切回赵敏 → 任务上有「要你动手」的点 → 退回批注在右栏、原件在中间画布 → 改参数 → 重出 v2。
说：人和工单是我们多出来的，beta5 里没有——硬冲突，以我们为准。

**7. 权限（1 分钟）** — 站在赵敏：尾卡右边那扇门是虚线灰块「完整价目表 · 仅 SD」；左下角「报价管理」进去顶栏「只读 · SD 助理」。切到王林彬全部打开。
说：权限分级会上说后置，这里只是演示级；助理能改临时价、审批人算 SD——09-21 定的。

**8. 「+」菜单（1 分钟）** — 输入框左边的 +：技能 = 让数字同事做（总结 / 列价目 / 核对 / 预览 / 生成，点了就跑，做不了的灰掉写原因）；连接器 = 本会话在读哪些源（项目文件库、计价规则库）。
说：技能不是挂在消息上的标签，是可以让它做的事；连接器回答"它读得到什么"。

## 跟 beta5 的差异点（讲给另一个组）

| | beta5 | 我们 |
|---|---|---|
| 壳 | 项目 → 空间，空间入口页，侧栏一级入口多 | 只改名 + 加了空间首页；侧栏结构没动，数据中枢多一档「产物」 |
| 会话层 | 已经采用了我们的设计 | 同 |
| 右栏 | 待定 | 报价板块（会议定的正主）+ 参数收集 + 报价结果；报价规则 tab 撤了 |
| 改价 | 无 | 临时价闭环：原价 → 新价 → 确认，仅本单；无价目可补价 |
| 价目表 | 无 | 独立入口（报价管理），会话里能问本单命中的那一截 |
| 材料识别 | 无 | 多模态入口 + 解析轨迹 + 每项参数的原文依据 + 识别 / 确认两态 |
| 人与工单 | **没有** | 站内信、工单、交接、退回、审批人复核画布——硬冲突，以我们为准 |
| 权限 | 无 | 演示级：SD / SD 助理两级 |
| 数字团队 | 有「专家」入口 | 保留我们的形态，空间可绑专家 |
