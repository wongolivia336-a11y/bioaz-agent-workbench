# DMPK 复杂报价长期治理架构

## 目标

页面继续使用现有 Workbench、参数卡、右侧报价板块和生成前确认流程。业务规则不再写进 React 组件，也不再由一条报价行同时承担实验事实、计价规则和展示结果。

规则基线为产品文档 `DMPK 复杂报价计价规则2.0`。在价表版本、ADA 板容量、整合报告、硬成本范围和取整时点未锁定前，系统保留待确认项，不自行补默认答案。

## 分层

1. 实验事实层：动物分组、实验阶段、物理采集事件、检测任务和报告任务。事实只描述发生了什么，不带价格。
2. DMPK 策略层：决定服务是否生成收费行、是否复用、采用哪种计价模式、哪些系数适用，以及需要谁确认。
3. 通用计价内核：执行按单位、固定价、按板、阶梯价、最低计费量、系数、币种转换和取整，输出完整计算轨迹。
4. 展示适配层：把结果适配成现有 `QuoteLine`，供右侧板块、按组明细、Word 和 Excel 预览共用。

## 稳定边界

- `lib/workbench/pricingEngine.ts` 是无业务含义的纯计算内核。
- `modules/dmpk-quotation/pricing/policy.ts` 保存 DMPK 2.0 策略和版本常量。
- `modules/dmpk-quotation/pricing/pending.ts` 保存待确认事项及正式报价发布门禁。
- React 组件只能发出用户意图和展示结果，不能计算费用。
- 所有金额都必须从同一份计算结果生成，页面、Word、Excel 不允许各算一遍。

## 迁移顺序

### 阶段一 计价内核

支持按单位、固定价、按板、阶梯价、最低计费量、BA 系数、地区系数、硬成本豁免和人民币转美元。旧报价行保持兼容，新行可以逐项迁移。

### 阶段二 事实模型

把统一的“组数 × 每组只数”升级为逐组动物清单；新增物理采集事件，使一次采血可以服务多个 PK、TK、BA 或 ADA 检测任务而只收一次采集费。

### 阶段三 业务任务

拆分 In Life、临床病理、方法开发、样品检测、ADA、病理组织和报告任务。每个任务独立选择价目、计价模式与确认项。

### 阶段四 正式报价门禁

按客户、价目负责人、技术三类责任方展示待确认事项。阻断项未解决时可以保存草稿和查看已确认小计，但不能发布正式总价。

### 阶段五 输出与回归

Word、Excel、页面均读取同一个计算快照。固定复杂案例覆盖采集复用、逐组数量、30 个保底、ELISA 阶梯、ADA 按板、BA 1.5 倍、地区系数和硬成本。

## 当前进度

通用计价内核、DMPK 2.0 策略、待确认门禁和实验事实层已接入原型。逐组动物与物理采集事件可以在原参数卡内编辑；PK/TK 共用采血只生成一条采集费。样品检测按待测物拆行，只有明确适用的任务才执行 30 个保底；ELISA 使用阶梯价，BA 方法费与检测费应用 1.5 倍后再应用地区系数。临床病理、ADA、病理组织和报告规则均有独立编译与回归测试，未确认的责任项会保留在明细并阻止发布正式总价。报价金额统一输出 USD，旧的 Word 30% / Excel 15% 管理费口径已移除。
