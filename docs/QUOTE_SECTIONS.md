# 报价板块：右栏的「参数状态 + 单价」

出处：2026-09-21 澎立报价开发组会议（DMPK 复杂报价）。会议要点见 [当天工作日志](worklog/2026-09-21-工作日志.md) 末段。
本文记这一轮落在原型里的东西：板块怎么定、行从哪儿来、改价怎么闭环、价目表的门开在哪儿、什么没做。

## 1. 三条共识 → 原型里的落点

| 共识 | 落点 |
|---|---|
| 右栏不再收集 / 编辑参数，只做「已收集参数的状态展示 + 对应单价」；改价是临时调价的唯一路径 | 新面板 **报价板块**（`sections`），常驻 tab，账一有行就切过去。参数收集 tab 保留（文件识别的逐项确认在那儿），但不再是默认 |
| 完整价目表不进对话，独立入口，有权限的人（SD 级）进 | 板块面板底部「查看完整价目表 →」，开报价管理的标准价格 tab；页首多一行边界说明 |
| 参数不开放编辑，权限分级后置 | 改价不设门槛，谁改记谁（账号名）。价目表那扇门用账号切换器做演示级门槛：审批人 / 负责人是按钮，撰写人是一行说明 |

## 2. 板块 = 工作包

`QuotePackage` 就是板块。会上点名四个 + 两个配套，顺序固定：

| id | 板块 | 说明 |
|---|---|---|
| `pk-tk` | PK / TK 样品采集 | 采血、方法开发、样品检测 |
| `tox` | TOX | 临床病理、细胞因子、流式、给药、观察、解剖… |
| `ba` | BA | 纯生物分析：方法开发、样品检测（没有采血——样品是客户送的） |
| `ada` | ADA | 留样、方法开发、筛选检测 |
| `animal` | 动物使用 | 动物费、饲养 |
| `report` | 报告与交付 | 报告 |

一场实验涉及哪几个就挂哪几个（`summarizeLines` 只返回有行的包）。

## 3. 每行四要素

`QuoteLine` 上加了 `analyte`（待测物）和 `method`（检测方法），加上原有的 `qty / unit` 和单价，就是会上的四要素。
面板里一行两行字：**名字 + 「数量 × 单价」**，下一行 **待测物 · 检测方法**。没有待测物的行（采血、动物、报告）第二行不出。
第一版是每行一张 2×2 的表（四个标签四个值），27 行下来整栏都是字，用户说太杂——标签去掉，靠位置说话。
描述性细节（组别、核心 / 卫星、时点）、来源、公式、规则**不进板块面板**——要看去「报价明细」和「报价规则」。

**板块可折叠**：段头写名字、几项、几项待定、小计，折着也读得出状态。默认只开一个——第一个有待定项的板块，都没有就开第一个。
27 行的 BB-001 折完一屏放得下：一个板块展开 + 四条段头 + 合计 + 价目表的门。

## 4. 行从哪儿来

`buildDmpkQuoteLines(fields, sources, { fieldsOnly })`：

- **读过方案**（sources 里有 `protocol`）→ BB-001 那份按关系推的细账（27 行，5 个板块）。
- **没读过方案** → 十四项推出来的粗账：采血 / 样品检测 / 方法开发 / 动物费 / 饲养 / 报告各一行。
  哪一项参数还没填，对应的行就是「缺参数」并 `dependsOn` 指回那一格——人在参数卡上每填一项，右栏就多亮一行。
  板块按检测类型定：PK → `pk-tk`，BA Only → `ba`，TOX → `tox`（多一行「毒性终点分析」，价目是草稿，无价目）。
- **退回会话** `fieldsOnly: false` → 没有行。它的纸面是批注锚着的固定件，换了账批注就没处落。

单价走 `catalog.ts` 有的那几档；采血 ¥130 / 份跟 BB-001 一样是照 beta3 反推的，不在价目表里。

## 5. 改价闭环

单价旁「改价」→ 就地展开：**原价 ¥X / 单位 · 价目 v1.0.13 → 输入新价 → 确认**。回车也算确认，Esc 取消，**失焦不落**
（报价明细那边失焦就落，是老行为；会上要的是显式确认）。落下之后：

- 单价换成新价，旁边挂「临时价 · 原 ¥X」，一键「恢复」
- 数字同事在对话里落一句「已按临时价 ¥Y 记「…」（原价 ¥X），仅本次报价，价目表不动。」
- `manualPrices[lineId] = { price, by: 账号名, at }`，只在会话里，价目表一个字不碰
- 出过版的会话进入 `quoteStale`，版本卡上「重新生成」

无价目的行按钮叫「补价」，编辑器第一行写「系统无价目 · 本单补价」，落下后 chip 是「临时价 · 本单补价」。
这对应图谱的「仅识别概念 → 用户补价」：金额留在本单、标记为用户提供、不按零元。

## 5b. 「报价规则」tab 撤了

原来那个面板列了四条「本次命中的规则」，两条其实是单价（动物费、报告费），底下还有费用明细弹窗和「对话编辑」——
跟板块说的是同一件事，还多了一条改价的路。先是砍成只剩规则，用户看了还是觉得跟板块打架，09-21 晚定了撤掉 tab：

| 它剩下的 | 去处 |
|---|---|
| 国内区域 / PK 模板 v8 两条规则 | 板块底部一行「本单规则」小胶囊，铅笔仍是进对话改 |
| 「N 项没有价目」 | 板块里一行一个「待补价」，不再说第二遍 |
| 全局四个链接 | 就是「查看完整价目表 →」那扇门；进去四个 tab 都在 |

DMPK 右栏只剩 参数收集 / 报价板块 / 报价结果（+ 菜单里那几个）。肿瘤报价那边的规则面板没动。
顺手删了两份整文件都没人引用的旧样式（`dmpk-strategy.css`、`dmpk-adjustment-drawer.css`）。

## 5c. 在对话里列本单命中的价目

会议共识 2 是**完整**价目表不进对话；用户要的是另一件事：在会话里问一句，数字同事回一张**本单命中的**价目表。
板块底部一颗「在对话里列出本单价目」，或者直接打「这单用到了哪些单价」这类话（`本单/这单/命中/用到 + 价目/单价/价格`，
带「改 / 调」的不算，那是改价）。回的是一张表：费用项目 / 板块 / 单价 / 本单用量 / 状态——同一档价被几行用折成一行
（游离 IMQ 和 MMAF 的样品检测都是 ¥180 那档 → 一行、322 份、2 行），临时价标出原价，无价目的另起一段。
问的那一刻的快照，不随后面改价变。谁都能问——那不是完整价目表。`modules/dmpk-quotation/catalogHits.ts`。

## 5c'. 板块的尾卡，和 composer 的「+」菜单

板块底部收成一张浅底尾卡：合计 / 本单规则 / 两扇门，细线隔开；两扇门是等宽按钮（没权限的那扇是同样大小的虚线灰块，位置不变）。

「+」菜单里的 技能 / 连接器 原来在会话里没有说服力（把「报价参数收集」挂成 chip 是什么意思？）。会话里改成两种形态，
首页不变：

- **技能 = 让数字同事现在就做的事**：总结当前会话、列出本单命中的价目、核对已有信息并重新计算、预览完整参数、生成 / 重新生成报价单。
  点了就跑，不挂 chip；做不了的灰掉写原因（没账 / 参数没齐 / 没改动）。这些本来都是对话里一句话能触发的，这一列是目录。
  下面「自动运行中」列数字同事自带的技能（参数收集、规则匹配、模板生成），只读，说明它们一直在跑；规划中的标「规划中」。
- **连接器 = 这条会话在读哪些源**：本会话在读（项目文件库、计价规则库）/ 已连接·本会话不用（PubMed）/ 未接入（待审批、未连接）。
  只看不挂，底下一句「单价从计价规则库来，材料从项目文件库来；接入与授权在数字团队 › 连接器里管」。
  `lib/workbench/composerAttachments.ts` 的 `ComposerSessionAction`，会话通过 `sessionActions` 递进 `WorkbenchComposer`。

## 5d. 权限（演示级）

会上说权限分级后置；用户要在原型里用左下角账号切换器演出来，于是账号上加一个级别（`grade`：SD / SD 助理），
`lib/workbench/permissions.ts` 按它推三个布尔。用户 09-21 晚拍板：助理能改临时价；审批人算 SD。

| 级别 | 板块里改临时价 / 补价 | 看完整价目表 | 后台改底表 |
|---|---|---|---|
| SD（王林彬 审批人、李林 负责人、孙桦） | ✓ | ✓ | ✓ |
| SD 助理（赵敏、陈默） | ✓ | ✗ 一行说明 | ✗ 后台只读 |

只读的做法：没权限的动作不出现（铅笔不出、门不开），行上其余不变；后台标准价格页顶栏「只读 · SD 助理」、
页首一行锁说明、行不响应、没有导入 / 新增。级别显示在左下角账号行「审批人 · SD」。

## 6. 完整价目表

报价管理 → 标准价格就是它：11 项、按 PK / BA Only / TOX 筛（= 板块）、按分类筛、有草稿 / 已发布状态。
从会话的门进来时页首多一行：「这是全局价目表：在这里改的价会进入下一个发布版本……只想改这一单的单价，回到会话点改价。」
门的演示级门槛：`viewerRole !== "author"` 才是按钮。

## 6b. 对照 P0 工程方案（五层链路版）：八维与几条规则

09-21 晚拿到《DMPK 复杂报价 P0 工程方案（五层链路版）》。第一层的「8 维提取 Schema」就是会上说的「八维」，
原型的参数模型不动，按下面这张表对上；对不上的几处当晚补了。

| 八维 | 落到原型的哪儿 |
|---|---|
| ① 动物 | 字段 `species` |
| ② 组别 | 字段 `groupCount`；核心 / 卫星只在材料面板里读得出，参数模型没分 |
| ③ 数目 | 字段 `animalsPerGroup` |
| ④ 实验操作 | 板块里的行（给药 / 采血 / 临床病理 / 剖检…），不是字段 |
| ⑤ 实验操作次数 | 字段 `bloodPoints`、`cycle` |
| ⑥ 检测项目 | 板块本身（PK/TK · TOX · ADA），字段 `assayType` 只挑一个——多选 + 按组参数没做 |
| ⑦ 检测方法 | 字段 `method` |
| ⑧ 检测数量 | 每行的 `qty` |

材料面板（`MaterialsPanel` → `SourceCard`）按 `ParsedFact.dim` 排序、行首标 ①–⑧，顶上一行「按八维提取 · 读到 n / 8 维」；
没标维度的（聊天里的交付要求）排最后。`lib/workbench/sources.ts` 的 `ExtractionDim` / `extractionDimLabels` 是唯一的定义处。

当晚补的几条（都在 `docs/worklog/2026-09-21-工作日志.md` 里有细节）：

- **不适用**：BA Only 不问动物参数，`applyDmpkApplicability` 把 species / animalsPerGroup / groupCount / cycle 标 `notApplicable`，台账写「不适用」不算欠。
- **少于 30 按 30**：第三层引擎规则，按化合物执行。`buildFieldLines` 里 `billedPerAnalyte = max(实际, 30)`，公式里实际数和计费数都写；后台规则页与规则助手例句同步改。
- **人工输入项**：猴类价、折扣、其他费用。食蟹猴使用费从「价目表有价」改成 `no-catalog` 待补价；`QuoteAdjustments { discount, otherFees }` 挂在会话上，
  板块尾卡多一行「人工调整项」，纸面的 Discounted / Total 按调整后算，Standard 按价目（补价的行按补的价，因为它没有别的价）。
- **影响提示**：`impactSentence(before, after)` 比前后两份账，参数卡发送、一句话补参数两条路的回复里都带「影响 X n 行；合计 A → B」。

## 6c. 积木卡、按组明细、审核人的那一包（09-22 凌晨补）

三件事都是 §6b 表里"没做"的，当晚接着做完了。参数模型仍然一个字没动。

**八维 = 参数收集的结构，积木 = 命中一块长一块**（09-22 早上心蕊定的形态；凌晨那版是参数卡底下另长一叠只读卡，两个东西叠在一个槽位，看不出关系，撤了）。
- 分组改了（`fields.ts`）：`DmpkGroupId = "base" | "package" | "delivery"`——**基础 ①②③**（种属 / 组数 / 每组只数 + 周期）、
  **板块 ④–⑧**（检测类型 / 分子类型 / 化合物类别 = ⑥，样品类型 = ④，采血点数 = ⑤，分析方法 = ⑦，待测物数量 = ⑧）、**报告与交付**。
  十四个字段 id 不加不减；每项带 `mark`（圈字）只做显示，不进 label（label 还要进对话和纸面）。板块那组的标题跟着检测类型走（`dmpkGroupsFor`：PK → 「PK / TK ④–⑧」）。
  右栏台账和 composer 参数卡读同一份分组——这就是"两边联动"。共用组件只加了 `ParamField.mark` 的渲染（不传就跟原来一样）。
- 主板块之外命中的板块（方案读出的 TOX / ADA，或人点「再搭一块」），在台账下面各长一张**同样的卡**（`packageBlocks.tsx` → `DmpkPackageCards`，
  用的就是 `.inspectorParameterGroup` 那副样子），卡上只摆 ④⑤⑦⑧ 各一行、文案压到一行，缺的写「待填写」点了去填；待确认 / 无价目一行一句原因。
  卡不另存定义，读的是账（`summarizeLines`）。「再搭一块」在台账最底下。
- ⑥ 检测项目多选的落法：`assayType` 仍单选、定主板块；再要哪个板块记在会话的 `extraPackages` 里，
  `buildDmpkQuoteLines(fields, sources, { extraPackages })` 接一段 `buildExtraPackageLines`（每个板块 2–4 行，缩自 BB-001 的细账），
  板块面板当场长出那一段，行大多缺参数，填一格亮一行；拆掉就收回。加、拆都进对话（多了几行、缺什么 + 影响提示）和快照（出过版再搭 → 待重出）。

**按组明细**（`报价明细` 面板顶上「按板块 / 按组」）。`QuoteLine.groupShare`：组 id → 这一行落在这组的数量；BB-001 的行按核心 / 卫星标（`share(core, sat)`），
十四项推的行按组数均分（`evenShare`）。`groupBreakdown` 每组按有效单价算金额，各组小计 + 整单项 = 按板块看的合计。
没标组的是整单项：方法开发、报告，以及触发「少于 30 按 30」的检测行——那条规则按化合物计，拆到组就不对了。

**审核人的那一包**（`lib/workbench/reviewBundle.ts`）。交接那一下会话打包：账折成的纸 + 每项参数的原文依据
（读自材料哪一节、原句；人改过原文的带 original；人填的；系统判定的不适用）+ 这一版改过什么（改价 / 补价 / 折扣 / 搭上的板块 / 出过几版，谁、何时）。
壳层原样挂到工单（`Ticket.review`），审核画布有包就读包里的纸（不再是固定件），多一个 tab「依据与变更」；附件预览读同一张纸。
没包的老工单照旧。批在这张纸上的锚点是 `f-<字段 id>`，`noteFieldMap` 加了这一组映射，退回后照样落回参数。
