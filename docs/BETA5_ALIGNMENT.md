# beta5 走查与对齐方案

> 2026-09-17。走查 `next-beta5.bioaz.cn`：专家 / 工具 / 数据中枢三个全局页、空间首页、
> 空间编辑弹窗、两条 DMPK 会话（一条补参中、一条已出报价并二次改参）、一条肿瘤报告会话。
> 目的：后续开发往 beta5 的方向靠，先弄清楚哪些是同一个东西换了名字、哪些真的冲突、
> 哪些是我们多出来要带过去的。

## 一、beta5 是什么形状

### 信息架构

```
左栏
├ 专家          数字角色的目录（DMPK报价专家（新版）/ DMPK报价专家 / 生成肿瘤报告专家），
│               卡片 → 弹窗：概述 + 技能列表。/research 直接落到这一页
├ 工具          生物计算工具目录（AlphaFold、ProteinMPNN、影像分析套件…），跟报价线无关
├ 数据中枢      四个 tab：文件 / 记忆 / 知识 / 产物；可按空间、按专家筛；回收站；「问问文件助手」
└ 空间 ＋       空间列表，每个空间展开是它的会话列表
   └ 空间       = 会话容器 + 绑定的专家（编辑弹窗：名称 / 可选专家 / 描述）
      ├ 首页     「Admin123，我能为你做什么？」+ composer（上传 · 专家 chip DMPK报价 / 肿瘤报告）
      │          + 本空间的数据中枢计数（文件 139 / 记忆 3 / 知识 2 / 产物 110）+ 本空间的专家
      └ 会话     对话列 + 右栏；标题 = 首条消息
```

**没有的东西**：人（成员、岗位、账号切换）、站内信、工单、交接、退回、审批人；
客户 / 委托方字段（空间只有名称、专家、描述）；报价管理后台入口；BioAZ Helper 那层中转。

### 会话层：他们已经采用了我们的设计

DMPK（新版）会话里的这些，跟我们的原型是同一副：
- composer 上方那张卡：「参数补全 · 信息完整时直接生成报价 / 请补全报价参数 / 全屏显示表单 / 还需填写 11 项 / 展开」，
  展开后按四组分页（检测类型 0/1 · 动物实验 0/5 · 生物分析 0/2 · 报告与报价 0/5），序号 + 必填 + 选项按钮，上一页 / 下一页
- 右栏「报价参数收集 · 计价参数随对话实时更新 · 1/12」，四组各带 进行中 / 未开始 / 已完成
- 运行记录「已完成任务处理 · 查看过程」折叠在回复上方
- 产物卡（Excel / Word · 预览 · 下载）钉在对话里

肿瘤报告会话也基本是我们的：预审核统计 chip（总计 / 通过 / 警告 / 阻塞 / 不适用 / 未执行）、
「已确认风险并继续生成」、「当前报告 v1」、Word 报告 + 交付包两张产物卡、「专家审核」卡 + 发起按钮、
composer 上「方案 Word 0/1 · 实验 Excel 0/1+」、右上角「风险回看」面板开关。

**所以对齐的主战场不在会话里，在会话外面：导航、空间、人。**

### 走查时看到的、不要照着抄的

| 现象 | 问题 |
|---|---|
| 参数卡里一行红字「请向用户询问分子类型，不得自行推断或填写默认值。」 | 这是给模型的指令，泄到了界面上。我们的规矩：空表单不预铺红字，红字留给真冲突 |
| 展开的卡固定高度，一个字段下面一大片空白 | 高度该由内容定 |
| 回复正文把 11 项缺项列了一遍，卡头又写「还需填写 11 项」 | 一件事说了两遍 |
| 「任务处理过程」三步：已创建运行任务 / 准备工具 / 完成报价处理 | 还是看不出读到了什么。我们的解析轨迹是每步「读出了什么 · 原文在哪」 |
| 用户消息是 `检测类型=PK检测 分子类型=小分子 …` 一串 key=value，会话标题也是它 | 那是表单序列化格式，不是人说的话；标题应该是任务名 |
| 出过报价后说「修改动物种属为：小鸟」→「本轮参数未通过权威校验，请根据字段提示补充或澄清」，两次，没有任何字段提示；右栏仍 13/13 已完成 | 没有「待重出」概念；校验失败不指向字段 |
| 「计算详情」按钮点了没反应 | — |

## 二、概念映射：我们的 → beta5 的

| 我们 | beta5 | 关系 |
|---|---|---|
| 项目（client）/ 资料空间（library） | 空间 | 同一个容器。beta5 没有 client / library 之分，也没有委托方字段 |
| 项目下的任务 | 空间下的会话 | 同 |
| 数字团队（数字同事 + 技能 + 连接器） | 专家（详情里列技能）；工具是另一页 | 专家 = 数字同事。连接器没有对应 |
| 新建任务首页（BioAZ Helper 识别意图 → 分派卡 → 确认） | 空间首页（composer + 专家 chip，直接选） | beta5 没有中转层 |
| 数据中枢（文件 + 问助手） | 数据中枢：文件 / 记忆 / 知识 / 产物；全局一级 + 空间一级 | beta5 更细 |
| 知识库 | 数据中枢 · 知识 | 合并 |
| 会话里的产物卡 | 同 + 数据中枢 · 产物 汇总 | beta5 多一个汇总视图 |
| 站内信 / 工单 / 交接 / 退回 | **无** | 冲突，见下 |
| 账号切换 / 岗位（撰写人 / 审批人） | **无** | 冲突 |
| QA 审核台 | 肿瘤报告会话里的「专家审核」卡（发起 → 派给审核小队） | 审核是数字专家做的，不是人做的 |
| 报价管理后台（价目 / 规则 / 字段 / 模板） | 未见 | 无价目深链没有落点 |
| 演示镜头 `?line=` | 无 | 演示脚手架，本来就要删 |

## 三、冲突清单

### 形制上的（改名字、挪位置就能对上的）

1. **左栏骨架。** 我们：新建任务 / 数据中枢 / 数字团队 + 项目树。beta5：专家 / 工具 / 数据中枢 + 空间树。
   → 「数字团队」改叫「专家」，「项目」改叫「空间」，「新建任务」这个入口收进空间首页。结构不动，改的是标签和入口位置。
2. **首页形态。** 我们的首页是全局的（先选项目再描述任务）；beta5 的首页是空间的（进了空间才有 composer）。
   → 跟 beta5：首页 = 空间首页。「没选空间就不能开任务」这条我们本来就有，只是现在把它做成了提示。
3. **右栏。** beta5 只有「报价参数收集」一个面板，没有 tab 栏。我们默认也只显示参数收集，其余从 ＋ 菜单加。
   → 不冲突。多面板（报价明细 / 报价规则 / 输入材料）是我们要带过去的东西。
4. **视觉。** beta5 更素：灰底、细线、几乎没有强调色；运行中也是同一种紫蓝点。我们的令牌能覆盖它，不需要新调色。
   圆角、字号跟我们的三档差不多。**不需要为了像它而改令牌。**

### 逻辑上的（要做决定的）

1. **beta5 里没有人。** 我们的 DMPK 送审 → 审批人退回 → 撰写人改 → 重出，QA 审核台的撰写人 / 审批人两端，站内信里的工单——全部依赖「人和岗位」。
   beta5 的审核是「派给审核小队」（数字专家），空间没有成员。
   → 这是唯一的硬冲突。两条路：(a) 提议 beta5 给空间加成员，我们的交接 / 退回落成「空间内的人之间」；
   (b) 把我们的交接降级：交接卡只记录「交给谁」和说明，不再依赖站内信，站内信整个先搁置。
   **建议 (b) 先行、(a) 提给工程师**——报价审批在 CRO 里确实是人做的，beta5 迟早要有人。
2. **空间没有客户字段。** 我们分 client / library，并给项目留了委托方、合同号的位置。
   → 先把「委托方」写进空间描述，`ProjectType` 保留但不再在界面上区分。
3. **没有 Helper 中转。** beta5 直接点专家 chip 开会话。我们的 Helper 识别意图 → 分派卡 → 确认，多一步。
   → 跟 beta5：专家 chip 直接开；Helper 只在「没点 chip、只打了字」时兜底识别。分派确认卡撤。
4. **无价目的出口。** 我们把「无价目」链到报价管理后台。beta5 没有这个后台入口。
   → 保留链接，落点改成「提醒后台维护」的一条记录；等后台在 beta5 里有位置再接。
5. **审核是谁做的。** 肿瘤报告：beta5 是数字专家审核小队；我们的 QA 审核台是人。两者不矛盾——小队先审、人再拍板——但 QA 审核台在 beta5 里没有容器。
   → 归入冲突 1。

### 不冲突、而且是我们多出来的（往他们方向靠时要带过去，不是删掉）

- 传文件出报价的**解析轨迹**（每步读出了什么 · 原文在哪），三类材料各喂不同段落
- **字段级原文依据**：台账小标点开是原句；人改过标「人填」
- **确认状态**：识别 / 已确认分开，「确认并生成」
- **报价行**：按工作包的小计 / 总额，算不出的行带原因——beta5 那张「费用明细」表（费用项 / 单价 / 数量说明 / 费用）可以直接由我们的行渲染
- **临时调价**：SD 手动单价压过价目表，仅本单
- **待重出**：出过版再改参数或单价，版本卡 / 确认卡 / 交接卡三处说——正好补 beta5「权威校验失败」那个坑
- **核对已有信息**：回扫材料和对话，找不回的明说
- **会话摘要**：顶栏一颗，交接说明预填
- **来源只读用户上传的**：工单带进来的附件不是材料

### beta5 有、我们没有的（借鉴）

- 数据中枢的 **产物 tab**（各会话产物汇总，带来源会话、所属空间）和 **记忆 tab**（对话记忆）
- 数据中枢的 **两级作用域**：全局一级 + 空间一级（`/spaces/<id>/hub?tab=…`）
- 空间首页上的 **数据计数 + 本空间专家** 两块
- 专家卡片 → 详情弹窗（概述 + 技能）这一形态，比我们「数字团队」整页更轻
- 「工具」目录——跟报价线无关，先不管

## 四、怎么改（建议顺序，仍是加法）

> 2026-09-20 跟用户过了一遍：第 1、2 条按第五节的口径做了；第 4 条**不做**——人和工单以我们为准；
> 数字团队不改名为「专家」；知识库不改名；第 3 条留到下一轮。

1. **词表对齐**（改标签不改结构）：项目 → 空间。~~数字团队 → 专家~~、~~知识库 → 数据中枢 · 知识~~ 不改。
2. **点空间进空间首页**：在原来的全局首页上加两样（标题说这个空间、一行本空间计数），快捷卡按空间绑定的专家过滤。
   Helper 分派保留——它是我们的兜底，不是要撤的东西。
3. **数据中枢加 产物 / 记忆 tab、空间一级作用域**：产物值得做，留下一轮；记忆先问清楚是什么。
4. ~~交接降级、站内信搁置~~ **不做。** 站内信 / 工单 / 交接 / 退回全部保留，以人员职能和工作流转为准；
   「空间要有成员」作为需求提给工程师。
5. **把「我们多出来的」那一节整理成给工程师的清单**，逐条对到 beta5 的会话里：哪个组件、放哪、数据从哪来。设计依据都在 `docs/DMPK_SOURCE_PARSING.md`。
6. 不做：为了像 beta5 改令牌；复制它的红字提示、固定高度卡、key=value 标题。

## 五、第一轮落地（2026-09-20）：词表 + 空间首页 + 专家绑定

用户拍板的边界：**人和工单以我们为准**（站内信 / 工单 / 交接 / 退回全部保留）；数字团队保留我们的形态，
不另加「专家」入口；收件箱保持图标；「产物」tab 留到下一轮；知识库不改名。改动全是加法。

- **词表**：界面上「项目」→「空间」（侧栏分组、新建 / 重命名 / 删除、选择器、提示语、数据中枢与工单的筛选器
  「全部空间」、空间助手）。代码标识符 `project` / `ProjectType` 一个没动；「资料空间」照旧；
  文件种类里的「项目资料」是分类名不是容器名，也没动。
- **空间首页**：进它的门是侧栏行 hover 的 ↗ 和菜单里的「进入空间」——**点行本身仍是开合**（第一版做成点名字进首页，用户当场否了：
  看树是最频繁的动作，不能变成导航）。首页 = 原来的全局首页 + 空间名进顶栏面包屑 + 快捷卡小字写是哪位数字同事 +
  输入框下面一块「空间概览」（三张同款小卡：文件 / 产物 / 任务；前两张进数据中枢这个空间，后一张展开侧栏那棵树）。
  第一版是一行裸文字「本空间 · 2 文件…」，形制跟卡片不是一套，撤了。
  **不建任务**——任务在第一句话发出去时才存在，这一点跟原来一样。没进空间的全局首页一个像素没变。
- **空间 ↔ 专家绑定**：`WorkbenchProject.coworkerIds?`（缺省 = 全部）；空间菜单多一项「设置空间专家」，
  `<Dialog>` 里勾选，至少留一位；空间首页的快捷卡按它过滤。这就是 beta5 编辑空间弹窗里「可选专家」那一栏。
- 快捷卡上写数字同事的名字，而不是另开一块「本空间的专家」列表——卡片就是专家，一件事一个门。
- **数据中枢「产物」档**（同日下午）：根级那张表上方一个分段开关「全部文件 | 产物」，产物档多一列「来源任务」，
  点它进那条任务的会话。这就是 beta5 的产物 tab 和它的「来源会话」列，但不另开路由——单个空间里本来就有「任务产物」那一道，
  缺的只是跨空间汇总和那一列来源。「记忆」tab 没做，先问工程师那是什么。

## 六、要跟工程师 / 产品确认的

1. 空间会不会有成员和岗位？没有的话，报价审批和退回在 beta5 里怎么落？
2. 报价管理后台（价目 / 规则）在 beta5 的哪里？「无价目」要链到哪儿？
3. 「DMPK报价专家（新版）」和旧版并行——旧版什么时候下？我们只对新版。
4. 数据中枢的「记忆」具体是什么：会话级摘要还是跨会话的用户记忆？决定我们快照往哪儿接。
