## 二、差别在假设，不在审美

| beta3 的假设 | 我们这版的假设 |
|---|---|
| 文件是黑盒的输入，输出是整个解析结果 | 文件是**来源**；解析是一次「阅读」，要留下**人能核对的痕迹**：哪一节 → 哪个事实 |
| 校验器知道的全部摆出来 | 只摆**现在需要人做的**，其余一键可达 |
| 待处理 = 一个文本框 | 待处理有**类型**（对应控件）和**归属**（对应去哪儿） |
| 报价在最后算 | 能算的当场算（这一轮没做，见「留到下一轮」） |
| 对话里说一遍、右栏再说一遍 | **一件事只在一个地方说** |

## 三、长在哪

### 1. 来源层 `lib/workbench/sources.ts` —— 多模态的口子

附件（`ComposerAttachment`）一个字不改，旁边加一层：

- `SourceKind` 看文件名定格式（docx / pdf / xlsx / image / text）
- `SourceRole` 由解析第一步判定：方案 / 样品清单 / 上一版报价 / 参考。传旧报价进来喂的是价格，不是实验概览
- `ParseStep { title, result, anchor, tech }`——每步**做了什么 · 产出几个 · 原文在哪**
- `ParseResult { patch, facts, pending }`——`patch` 落到现有十四项；`facts` 是读到但没格子放的；`pending` 分四类
- `SourceParser { kinds, parse }` + `parseSource()`。接 PDF、接 OCR 是**再注册一个 parser**，调用方不改；没有 parser 能读的格式也留一条「尚未接入」的轨迹，不静默吞掉

**现状是折中**：只有一个 mock parser，读什么格式都返回 BB-001 那一单（第一步如实报格式）。
图片那条并没有真的 OCR——演示上「都能解析」，文档里要说清楚。

### 2. 解析轨迹 = 原来的运行记录 + 两样东西

沿用 `.agentRun / .timeline` 骨架，`runSteps` 从 `string[]` 放宽成 `(string | ParseStep)[]`，
旧的三种运行一个字不用改。多出来的只有：每步一行「读出了什么」，一枚「原文在哪」的小标。
跟「整理实验事实 × 30」的全部差别就在这两样上——人对着它能核，「7 组」对不对，翻表 2 就知道。

步骤逐条揭开（360ms 一步），不是一次亮全：先判类型、再翻目录、再一节一节读，这个节奏本身就在说「它是怎么读的」。

### 3. 待处理四类，各回各家

| 类 | 谁做 | 落在哪 |
|---|---|---|
| 缺参数 | 用户 | 参数卡（现成的） |
| 待确认 | 用户 | 参数卡，**原文给的候选排到选项最前面** + hint「原文：…」。只动顺序不收窄——原文不是词表 |
| 待补价 | 用户 / 有权限的人 | 这一轮没做 |
| 无价目 | 后台 | **不进参数卡**。进「报价规则」面板「N 项没有价目」，出口是后台标准价格。不给输入框——填临时价等于绕过规则 |

这一条就把 beta3 右栏那三分之一还回来了。

### 4. 读到但没格子放的，进「输入材料」

7 个动物组、37 个采样事件、7 个分析方法、42 项委托——不进字段，模型不动。
在「输入材料」面板里挂在来源下面，只读，数量写在标题上、明细折在下面。
37 行平铺在 320px 的一栏里是一堵墙，折成一行「37 项 · 479 份」才扫得动。

### 5. 文字和文件同发：文件为准

跟着一份方案一起发的那句话多半是指令（「按这份方案出 DMPK 报价」），不是数据。
一句话识别会把「DMPK」认成检测类型 PK，盖掉方案里写明的 TOX——实测踩到了。
所以同发时文字只补文件没写的；真要纠正文件，下一句话或参数卡都走正常路径，照样能盖。

### 6. 「总结对话」→ 会话摘要

需求真实（补了六七轮之后人会迷路），位置不对：composer 那一排是「你要发什么」，
摘要是「我想看看到哪儿了」。所以入口在会话顶栏，跟面板开关同一副长相。

它是从当前状态推出来的四段话（已确认 / 待确认 / 计价 / 下一步），不是问数字同事「你总结一下」
——它没有比台账更多的信息，所以不等、不转圈。钉在生成那一刻，跟运行记录同一个逻辑。
交接卡的说明栏预填它：接手的人要的正是这几句。只在说明栏还空着时填，人打过字就不盖。

## 六、P0-2 这一轮（2026-09-15 下半天做完）

### 1. 确认状态：机器读出来的是提议，人点过头的才是参数

文件认出来的值和人确认过的值，在台账上原来长得一样——而「转换确认模块」要区分的正是这个。

- 两态就够：`recognized`（文件认的）/ `confirmed`（人经参数卡、铅笔或「确认」动作落过的）。
  一句话里打出来的值是人自己说的，直接算确认，不进这张表
- **只标「识别」，不标「已确认」**：台账上多数行都是确认过的，每行挂一枚「已确认」等于什么都没说
- 三个数分开报：`11/14 · 识别待确认 11`。只报 11/14 的话，「11」里混着人没看过的东西
- 出口有三个：铅笔改一项（顺手确认）、右栏「确认全部识别项」（核过了一次点头）、
  报价前确认卡的「确认并生成」。**不拦**（P0-3 不单设门槛），但话写在按钮上——
  悄悄确认和拦住不让走，都不如把这件事写在手指要按的地方
- 转换确认模块 = 台账 + 输入材料 + 参数卡合起来，没有新开页面。beta3 右栏想做的就是它

### 2. 报价行：十四项之外的那层账

一份真实毒理报价不是「每组 N 只 × 单价」一句话：核心组卫星组只数不同、采血点不同；
同一批血清 6 个分析物，3 个平台未定；4 组免疫分型采血根本没价目。
**按实际关系取数、算小计和总额**要的是一行一行的账，十四项是这份账的归一化摘要。

- `lib/workbench/quoteLines.ts`：一行 = 一个范围上的一项服务，`qty × 单价 = 金额`，按工作包归组；
  小计和总额从行上算，不另存
- 数量**按关系推**，公式写在行上给人核：「2 只 × 16 点 × 4 组」——「128 份」对不对，翻表 3 就知道
- **算不出的行也是行**：缺参数 / 待确认 / 无价目各带原因留在账上。只列算得出的，总额看着像整单，
  其实少了一截，人不知道少的是哪几行。前两种点「去填这一项」直接到那一格；无价目的出口在「报价规则」
- 状态跟着字段走：「分析方法」选了 LC-MS/MS，三个平台未定分析物的方法开发和样品检测两行当场变已计价，
  走对应那档价；「报价区域」没填，报告那一行缺参数
- 「计算依据」改名「报价明细」，**有行就开，不等参数齐**；「费用明细」弹窗读同一份行——两处不能各有一套数
- 没读过方案的会话没有行（十四项推不出这些关系），费用明细仍是原来那四行示意

### 3. 临时调价：手动价压过价目表，价目表一个字不动

- 手动价**不写在行上**（行是从事实推出来的，重算就没了），按行 id 记在会话自己的 `manualPrices` 里；
  `priceCatalog` 只读，别的报价看不见
- 改过的行并排显示「SD 手动 ¥X」和划掉的价目价——两边都在，人才知道自己改的是哪一档、改了多少
- **无价目的行也能给价**：那正是「待补价」的出口——后台没价，SD 现场给一个，只作用于这一单
- 对话里改报告费（`DmpkEditProposalCard`）和明细里改单价是**同一件事**，写进同一张表；有账时账上的报告行跟着变
- 每一次改动都进对话：报价复核是算术，改过哪一档单价必须能翻到
- 「SD」指谁甲方没说清，收成常量 `MANUAL_PRICE_BY`，确认后改一处

### 明确没动的

十四项 / 四组 / `parseDmpkRequest` / stage 机 / 参数卡 / `ComposerAttachment` / 来源层；
`quoteData.ts` 那张 TK-2039 纸面和 `QuotePaper`（退回场景的固定件）；`priceCatalog`。

## 七、P0-1 这一轮：原文依据到字段（2026-09-15 晚）

### 1. 一格一句，不是一份材料一句

「保留原文依据」不是轨迹里写一句「§1 实验设计」就完了：台账上「4 周」这一格，人要能点开看到原文写的是
「观察期 28 天（Day 1 – Day 28）」。所以原句跟着值走：

- `ParamField.source?`（可选）：`document` = 哪份材料、哪一节、原句；`ParseResult.patchSources` 一格一句，
  跟 `patch` 分开放——`patch` 的形状要跟一句话识别的输出一样，两条路合进同一个 `setFields`
- 台账行值后面一枚小标写锚点（「表 2」「§4」「第 7 条 · 客户 王工」），点开在这一行下面插一张小卡：
  材料名、位置、原句。不悬浮、不压暗——320px 的一栏里悬浮层没地方摆
- 小标长在行按钮里（行本身点了是去改），所以它把 click **和 pointerdown** 都拦住：
  卡片的「点外部关闭」听的是 document 上的 pointerdown，不拦的话点小标先关后开，永远关不上
- 「输入材料」里每份来源下多一段「这份材料喂了哪几项」：参数名、值、锚点——转换确认模块「展示提取信息」那一半

### 2. 人改过的格子换成「人填」

值已经不是原文说的那个了，再挂着原句等于给一个不支持它的证据。所以：

- 改过 → `source = { kind: "manual", original }`，小标换成「人填」，卡里写「原文为 X，已改为 Y」+ 原句
- **只在盖掉了一个原文来源时才出现**：原来就是人填的格子改了还是人填，不长小标；
  「方案说 4 周、人改成 2 周」正是审批人要一眼看到的那种格子
- 改回跟原文一样的值也不恢复 document——那是人拍的板，不是读出来的

### 3. 三份不同的材料，喂报价的不同段落

`SourceKind` 加 `pptx`，`SourceRole` 加 `chat`；parser 按格式分三个 mock：

| 材料 | 认得出什么 | 认不出什么 |
|---|---|---|
| 方案（Word / PDF / PPT / Excel）→ BB-001 | 11 项 + 分组 / 采样 / 方法 / 委托四类事实 | 报价区域 |
| 给药分组表截图（图片）| 种属 / 组数 / 周期 3 项 + 分组事实；轨迹多一步「OCR 识别表格 · 7 行 × 5 列」| 分析方法、报告格式——不在那张表上 |
| 微信聊天记录（文本，或文件名带「微信 / 聊天」的截图）| 报价区域 / 语言 / 格式 3 项，原句是客户那条消息；轨迹「识别说话人 · 客户 2 · 商务 1」；交付时间没有格子，进事实 | 实验设计 |

叠着传时后传的盖前传的，**每一格的来源指向真正提供它的那份**：三份传完，种属的小标是截图的「表头」，
报价区域的是聊天的「第 7 条 · 客户 王工」。没有 parser 的格式（.zip）走「尚未接入」那条轨迹，不静默吞掉。
都不是真解析——接 docx 结构、接 OCR 时是换或加一个 parser，调用方不改。

### 明确没动的

十四项 / 参数卡 / 报价行 / `priceCatalog` / 肿瘤线。`ParameterLedger` 的 DOM 没套新层——
`.inspectorParameterField:last-child` 去掉末行底线，套一层每颗按钮都成了 last-child，两条线的底线全没。

## 八、收尾这一轮（2026-09-16）

### 1. 纸面读账，不读固定件

`QuotePaper` 原来直接读 `quoteData.ts` 那份 TK-2039（美元、寡核苷酸毒理）。有报价行的会话，
预览里看到的必须是同一批数，否则预览没有意义。所以纸面吃一份同形状的数据（`QuotePaperData`），
`quotePaperFromLines` 把行折成条目 / 参数 / 小计：计算表左边一行一项，单价是生效单价（手动压过价目，
旁边小字写「SD 手动单价 · 价目表 X」），算不出的行单价「—」并写原因——它们在纸上也得在；
Standard = 全按价目表的总额，Discounted = 含手动价的总额，两者差的就是 SD 调的那部分。
退回会话没有账，不传，纸面照旧是批注锚着的固定件。

### 2. 待重出：stage 记不住，单独算

生成那一刻记一份「字段值 + 手动单价」的快照，之后任一处变了就是旧的。改参数会退回 collecting，
改单价连 stage 都不动——所以不往 stage 里塞值。三处说这件事：报价结果的版本卡（chip + 「重新生成」，
改单价不经过参数卡，出口只能在这儿）、报价前确认卡（标题改「参数已更新，重新生成」，版本来源写「改参数后重出」
不再是「首次生成」）、交接卡（**不拦**，一行提醒 + 「先重新生成」——送出去的是旧的这件事得说在手指要按的地方）。

### 3. 核对已有信息并重新计算

人说「我说过了」的时候，该做的是回去翻，不是再问一遍。翻两处：传过的材料（按来源，找回的带原句）、
说过的话（一句话识别再跑一遍）。整个过程是一条运行记录：重扫 N 份材料 → 回读 M 条对话 → 逐项比对。
找得回的补上；找不回的**明说**「这几项材料和对话里都没有」——承认识别器会漏，不假装找到。
入口两个：对话里的「说过了 / 核对一下 / 重新计算」，和「风险与缺失项」面板底下那一行。

### 明确没动的
