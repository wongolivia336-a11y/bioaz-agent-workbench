## 二、差别在假设，不在审美

| beta3 的假设 | 我们这版的假设 |
|---|---|
| 文件是黑盒的输入，输出是整个解析结果 | 文件是**来源**；解析是一次「阅读」，要留下**人能核对的痕迹**：哪一节 → 哪个事实 |
| 校验器知道的全部摆出来 | 只摆**现在需要人做的**，其余一键可达 |
| 待处理 = 一个文本框 | 待处理有**类型**（对应控件）和**归属**（对应去哪儿） |
| 报价在最后算 | 能算的当场算（这一轮没做，见「留到下一轮」） |
| 对话里说一遍、右栏再说一遍 | **一件事只在一个地方说** |

## 三、长在哪

### 1. 来源层 `lib/workbench/sources.ts` —— 多模态的口子

附件（`ComposerAttachment`）一个字不改，旁边加一层：

- `SourceKind` 看文件名定格式（docx / pdf / xlsx / image / text）
- `SourceRole` 由解析第一步判定：方案 / 样品清单 / 上一版报价 / 参考。传旧报价进来喂的是价格，不是实验概览
- `ParseStep { title, result, anchor, tech }`——每步**做了什么 · 产出几个 · 原文在哪**
- `ParseResult { patch, facts, pending }`——`patch` 落到现有十四项；`facts` 是读到但没格子放的；`pending` 分四类
- `SourceParser { kinds, parse }` + `parseSource()`。接 PDF、接 OCR 是**再注册一个 parser**，调用方不改；没有 parser 能读的格式也留一条「尚未接入」的轨迹，不静默吞掉

**现状是折中**：只有一个 mock parser，读什么格式都返回 BB-001 那一单（第一步如实报格式）。
图片那条并没有真的 OCR——演示上「都能解析」，文档里要说清楚。

### 2. 解析轨迹 = 原来的运行记录 + 两样东西

沿用 `.agentRun / .timeline` 骨架，`runSteps` 从 `string[]` 放宽成 `(string | ParseStep)[]`，
旧的三种运行一个字不用改。多出来的只有：每步一行「读出了什么」，一枚「原文在哪」的小标。
跟「整理实验事实 × 30」的全部差别就在这两样上——人对着它能核，「7 组」对不对，翻表 2 就知道。

步骤逐条揭开（360ms 一步），不是一次亮全：先判类型、再翻目录、再一节一节读，这个节奏本身就在说「它是怎么读的」。

### 3. 待处理四类，各回各家

| 类 | 谁做 | 落在哪 |
|---|---|---|
| 缺参数 | 用户 | 参数卡（现成的） |
| 待确认 | 用户 | 参数卡，**原文给的候选排到选项最前面** + hint「原文：…」。只动顺序不收窄——原文不是词表 |
| 待补价 | 用户 / 有权限的人 | 这一轮没做 |
| 无价目 | 后台 | **不进参数卡**。进「报价规则」面板「N 项没有价目」，出口是后台标准价格。不给输入框——填临时价等于绕过规则 |

这一条就把 beta3 右栏那三分之一还回来了。

### 4. 读到但没格子放的，进「输入材料」

7 个动物组、37 个采样事件、7 个分析方法、42 项委托——不进字段，模型不动。
在「输入材料」面板里挂在来源下面，只读，数量写在标题上、明细折在下面。
37 行平铺在 320px 的一栏里是一堵墙，折成一行「37 项 · 479 份」才扫得动。

### 5. 文字和文件同发：文件为准

跟着一份方案一起发的那句话多半是指令（「按这份方案出 DMPK 报价」），不是数据。
一句话识别会把「DMPK」认成检测类型 PK，盖掉方案里写明的 TOX——实测踩到了。
所以同发时文字只补文件没写的；真要纠正文件，下一句话或参数卡都走正常路径，照样能盖。

### 6. 「总结对话」→ 会话摘要

需求真实（补了六七轮之后人会迷路），位置不对：composer 那一排是「你要发什么」，
摘要是「我想看看到哪儿了」。所以入口在会话顶栏，跟面板开关同一副长相。

它是从当前状态推出来的四段话（已确认 / 待确认 / 计价 / 下一步），不是问数字同事「你总结一下」
——它没有比台账更多的信息，所以不等、不转圈。钉在生成那一刻，跟运行记录同一个逻辑。
交接卡的说明栏预填它：接手的人要的正是这几句。只在说明栏还空着时填，人打过字就不盖。

## 六、下一轮顺序（已定：先 P0-2，P0-1 字段级依据紧随其后）

1. **确认状态**：字段两态（识别 / 已确认）+ 台账 chip + 「确认」动作；转换确认模块 = 台账 + 输入材料 + 参数卡合起来，**不新开页面**
2. **报价行**：`QuoteLine` 从 facts × 价目表推导；「计算依据」按工作包（PK/TK、TOX、ADA）列行、小计、总额；算不出的行写原因（缺参数 / 待确认 / 无价目）
3. **临时调价**：任一行「改单价」→ 行上记手动单价，标「SD 手动」，总额重算，留记录；价目表深链保持只读

5. 真解析：docx 结构、PDF、OCR——往 `dmpkSourceParsers` 里加，不改调用方
6. 「核对已有信息并重新计算」——有了字段级 `source` 之后顺手就能做
