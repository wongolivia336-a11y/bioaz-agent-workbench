## 一、补上「深色底上的文字」令牌

昨天留了个尾巴：**66 处 `color: #fff` 没地方归**。

它们不是"表面色"，虽然今天跟表面色一模一样——表面色以后可能调成米白，
而深色按钮上的字必须一直是纯白。写成 `var(--bioaz-surface)` 今天看不出差别，
**改令牌那天才会暴露**，那是最贵的一种错。

补了 `--bioaz-text-inverse`，66 处收掉。
验证：`token-diff` 比 1706 条 `color` 声明，**0 处变化**。

### 顺带翻出脚本里一个藏得很深的问题

`color-snap` 的令牌表是 `颜色值 → 令牌名` **一对一**的。
但 `#ffffff` 现在有**两个都对的令牌**（surface 和 text-inverse），
后声明的会把前一个顶掉——于是 `background: #fff` 和 `color: #fff`
必然有一边拿到错的令牌，**而错哪边取决于它们在 tokens.css 里的先后顺序**。

这种"结果依赖声明顺序"的错，是最难在 review 里看出来的。
改成按角色查候选列表。

另外两处：

- `--ink: #111318` 被当成"一处待转换的颜色"数进去了。它其实是**旧别名层在
  定义自己**，换掉它会改变 `--ink` 在全仓库的含义，是另一个决定，
  不该混在一次"换个写法"的提交里。单独计数。
- 跳过的按原因分类打印出来了。**"角色对不上"那张表就是"下一个该补哪个令牌"
  的答案**——那 66 处白字一直挂在上面，补了令牌才收掉。只报一个总数的话，
  没人知道该往哪儿使劲。现在还剩 27 处，其中 18 处是"边框跟它的填充同色"。

## 二、参数卡改成三级（老师昨天指出的）

老师说这个之前改过、现在又犯了。查了一下确实：卡片只有**两级**——
一直铺开着，点卡片任何地方直接跳全屏。**中间那一级被跳过了。**

改成三级，一级一次点击：

| | 状态 | 有什么 |
|---|---|---|
| 一 | **折叠**（默认） | 只有卡头：「还需填写 N 项」+ 箭头 |
| 二 | 展开 | 分页 + 当前这组的字段，**这时才出现全屏按钮** |
| 三 | 全屏 | 四组一次列全 |

**全屏入口只在展开之后给。** 折叠态放一颗「一屏看全」，等于请人从什么都
没看见直接跳到最重的那一层，中间那级又被绕过去。

### 两个默认值，判据是「谁要求它出现的」

- **系统弹的 → 折叠。** 这张卡是数字同事说「还缺 3 项」时自己冒出来的。
  默认铺开等于每轮对话顶掉半屏聊天记录，而人这时多半只想看它说缺什么——
  缺几项写在卡头上，折叠态已经把话说完了。
- **人点的 → 展开。** 点右栏铅笔出现的那张，人已经说明了意图，
  再要他点一下才看得见，等于问他「你真的要改吗」。

同一个组件，两种默认。

### 一个不改就会天天犯的坑

展开状态**必须由会话持有，不能留在卡里**。卡只在「收集中」渲染，
而每发一轮参数都要经过「处理中」——**卡会卸载再挂载**。
状态放组件里的话，每一轮都被重新折起来，人得反复点开同一张卡。

改的是共用组件，所以 DMPK 和肿瘤报价一次都到位。

## 三、规则写进设计系统

两种默认值的判据、展开状态属于会话。
