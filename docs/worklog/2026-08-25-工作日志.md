## 今日

这一天做的是同一件事的两半：先把交接这件事从邮件里搬出来，再让被交接的东西能在原地被审。

先是**工单**。邮箱一直在用信封的外壳干工单的活——`MailItem` 早就带着 `action`、`actionLabel`、`contextProject`、`moduleId`，那已经是一张工单了。三个马脚都在既有代码里：状态字段长在消息上（可消息一旦发出就不该再变，会变的是被处理的那件事）；QA 驳回生成的是**邮件草稿**，意味着这次交接存不存在取决于有没有人记得点发送；而「加入已有对话」得从两条独立消息里反推出「这是同一件事」，那是系统在跟自己的隐喻较劲。改成工单之后，状态一翻交接就存在，不需要谁去点发送。

然后是**信息架构的三次收敛**。第一版把工单做成侧栏一级入口，很快发现第二个队列就是第二个会被忘记看的地方；第二版折进收件箱、首屏做成工单表，但到达面摊一张台账等于要求人先读懂台账才知道今天有什么事；第三版才落定：**一个列表，首屏是消息，状态降成筛选**。台账没被删，是化进列表了——工单行右边挂状态和当前处理人，「那件事在谁那儿」不用切视图就能读出来。同时补上了机器写进来的消息：数字同事之间的知会、系统的规则发布。这里划了一条线——**机机协作不产生站内信，除非它需要人**，否则收件箱会被机器人的交谈填满。

再是**批注模式**。甲方给了两份真实产物（Word 报价书 + Excel 计算表），读完发现我原型里那 6 条假计价项跟真实结构完全不是一回事：Excel 左半边 15 条计价明细带单价，右半边 15 个可编辑参数喂 9 行小计，而表格自己在第 22 行写着 `Yellow-highlighted fields are editable`——**那批黄格子就是批注的锚点**，不用另发明。据此重建：两种形态可切、共用一套锚点、选中文字就地弹气泡卡、右栏只做记录。批注模型跟 QA 的 `QaFinding` 同构，只多一个**建议值**——QA 的批注是「这句话有问题」要人读，报价的批注是「这个数应该是 6 不是 2」，能被下一版直接核验。

最后**面包屑接管导航**（站内信 › TK-2046 › 报价复核，逐级可点），驳回/归档接上真实流转（驳回 = 打回提交人、归档 = 落进数据中枢 + 收终态）。

## 踩的坑（都已修复，记下来避免重犯）

1. **PowerShell 批量替换毁了一个文件。** 单元素嵌套数组被拍平，`$p[0]` 成了字符 `o`、`$p[1]` 成了 `n`，整个 `WorkbenchShell.tsx` 里每个 `o` 被换成 `n`（`const`→`cnnst`），且不可逆。从 git 恢复重做了 13 处改动。**教训：含模板字符串/特殊字符的代码替换一律用 Edit 工具，不走 PowerShell。**

2. **grid 嵌 grid 的默认拉伸。** 消息列表被父容器分了 578px 固定高，没写 `align-content` 时三行把高度平分——65px 的行之间空出 127px，看起来像列表坏了。同类问题出现过两次（详情页宽度也是）。**这套 CSS 里 grid 嵌套很多，写新面板前先量再下结论。**

3. **量错比较对象两次。** 拿列表的内容盒比详情的边框盒，把已经修好的判成没修好。**有意义的比较只能是同层级比同层级。**

4. **portal 逃出作用域三次。** 全屏参数面板 portal 到 body 之后，先后逃出了行布局、hover 护栏、克制蓝三个作用域——`.parameterTaskCard` 和 `.dmpk-quotationModuleShell` 里装的不是外观而是**决策**。凡渲染到这两个作用域外的东西，都得把选择器写回去（用 `:is()` 扩，不复制）。

5. **磁盘损坏。** 今日末 `node_modules` 被写坏（抽查 262 个 package.json 有 8 个是二进制乱码），`next dev` 直接崩。源码和 git 对象库经 `git status` / `git fsck` 验证完好，重装依赖后恢复。**注意：之前记录的「`npm run build` 必然 EISDIR 失败」可能是同一个根因，不是构建配置问题。**
