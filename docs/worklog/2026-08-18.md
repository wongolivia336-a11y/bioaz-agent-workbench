## 一、肿瘤报告：同一个动作说了两遍，确认语跑到过程前面

三个毛病，根因是两类。

**文案重复**——`addUserEvent` 被写在 `setWarnings` / `setReviews` 的 updater 里面。React 会重复调用
updater（开发态 StrictMode 必然如此），于是「已确认风险并继续生成。」进了两次对话流。只有**逐条确认**
那条路会触发，「全部确认」走的是另一个分支，所以一直没被发现。

判据留这儿：**updater 必须是纯函数，播报是副作用，只能留在事件处理器里。** 顺带把 `Date.now()`
生成 id 也挪出了 updater——同一条消息拿两个 id 是同一个错误的另一种表现。

**顺序颠倒**——「发起专家小队审核」和「已确认全部专家建议」共用一个 `review` 锚点，而那个锚点
渲染在审核区块的**顶部**，于是确认语出现在它所确认的那段过程**之前**。锚点拆成
`review / review-confirm / review-followup` 三个，各自挂在对应的段之后。

**开场说了两遍**——附件那条气泡写死一句「开始」，紧跟着 `startValidation` 又发一条「开始校验」。
附件和动作本来就是同一次发送，合成一条。

**途中发现的**：校验开始前、以及生成阶段发出去的消息会**直接消失**——它们被挂在还没渲染的区块上。
锚点重排时一并修了。

## 二、右侧面板：tab 和图标差 5.5px

用户说"感觉没对齐"。量出来是：tab 文字光学中心 y=47，`+` 和全屏键 y=41.5。

成因是两套基准。tab 栏是 `align-items: flex-end`（贴在 hairline 上），而图标组是
`align-self: center`（在 58px 的栏里居中）。左右也各差一截——tab 文字比正文左边线右 8px，
图标比右边线出 6px。

改法不是"把 41.5 调成 47"。给这条栏三个值——标签行高、离 hairline 的距离、正文留白——
tab 和图标都从这三个值推出来，**改其中一个不会让另一个掉队**。DMPK / 肿瘤报告 / QA 三处实测：
所有 tab 文字、`+`、全屏键共线，左右两端与正文边线齐平。

顺手清掉一组**从来没命中过**的 CSS：`.topbarActions` 那十几条规则，容器里永远是空的。

## 三、分界线可拖拽

面板左边那条线变成抓手。宽度写在**工作区**上而不是面板上——`--panel-width` 是工作区那条
`grid-template-columns` 读的值，写在面板自己身上父级列宽不会变。三个模块里面板都是工作区的
直接子元素，所以 `parentElement` 就是它。

拖动过程直接写 DOM 变量、不走 state：每帧 setState 会把整个面板重渲一遍，拖起来是顿的；
宽度回到 state 只发生在松手和键盘调整时，用来报给读屏。

夹在 320–760px，且对话列不低于 420px。双击回到各模块自己的默认值（DMPK 320 / 另两个 400，
所以重置是"删掉内联覆盖让 CSS 重新生效"而不是写死一个数）。≤1023 面板本来就是浮层，抓手隐藏。

## 四、资料助手：放大不是把胶囊拉宽

原来点放大只是 `width: 1100px`，读长答案时仍然是一条压在文件表上的窄带。

改成一个**次级界面**：铺满面包屑以下、sidebar 以右的一整格。实现上是工作区网格里显式落在
第 2 行的绝对定位子项——包含块正好是那一格，**顶栏和侧边栏天然留在外面，不用去算它们多高多宽**。

它读起来是一个会话窗：完整问答串带出处、composer 是底部居中的胶囊。窗头明说
「临时会话，不会存进左侧任务」——这一屏没有对应的任务，Esc 或窗头那颗键收回胶囊，
侧边栏任务列表实测不变。

## 五、页头：两行四格，一格一个问题

三屏各自为政。数据中枢把面包屑、搜索、筛选、排序、上传五件事塞在同一行；数字团队的搜索框在
第一行、而它的 placeholder 跟着第二行的 tab 变，两者隔着一条分隔线差 100px；邮箱顶上是
**48px 的空带**，上下各一条线。

定了四格，一格回答一个问题：

| 格 | 回答 | 形态 |
|---|---|---|
| 行1 左 | 你在哪 | 面包屑 + 作用域选择器（它换的是路径） |
| 行1 右 | 这一屏最想让你做的那件事 | **至多一颗**实心按钮 |
| 行2 左 | 你在看哪一部分 | 下划线 tab（只换整块内容的那种） |
| 行2 右 | 作用于当前这部分的工具 | 搜索/筛选/排序，全幽灵态 |

两条硬规则：**两格都空时整行不存在**；**整个页头只有一条线，画在底部**，行与行之间不画。

那 48px 空带是个真 bug：工具格里塞着一个永远空的 `.topbarActions` 包装，于是
`:has(.topbarToolLayer:empty)` 永远不成立——工具格自己被藏了，行却留着。邮箱页头 **111 → 64px**。

顺带对齐的：面包屑/tab/工具/主操作四者现在都收在正文那条轨上（第二行原来自带 20px 内距，
比第一行各缩进 20px）；页头控件高度收成两档，34px 动作与工具、28px 作用域芯片——
原来是 25/28/34/36 四种混着，作用域选择器靠内距撑出 25px，紧挨的新建键写死 28px。

**一处按规则判、没有照搬的**：邮箱的收件箱/已发送/草稿留在左列列头，没搬进顶栏。规则是
「换整块内容的 tab 归页头，只换某一列的归那一列」——切信箱只换左列，右边读信/写信区不动。

## 七、QA 已落地的三件

**响应式（那张竖排截图）**——`.breadcrumb` 的 `white-space: nowrap` 只写在 `≤1023` 的媒体查询里。
1024–1280 这一段面板占 400px、QA 顶栏被挤进 446px 的内容列，中文没有词边界，一挤就一字一行：
实测 **139px 宽 × 158px 高**。nowrap 提为所有面包屑的基础规则，并给 QA 顶栏定了让位顺序——
路径可截断，角色徽标 ≤1180 先收，版本和状态一步不让。1100px 下实测 288×18 单行，工具组完整。

**思考链**——原来是 `mailReviewRunning && <ActivityChain>` 渲染在消息列表**外面**，跑完整条卸载。
现在跑批是一条**消息**，跑完折叠成「已完成 202612011511 第三版审核 · 查看过程」留在时间线上。
一个 QA 会话跨好几版、AI 会跑好几次，得能回头看第二版当时它说了什么。

**顺手挖出的旧 bug**——从邮件进 QA，那次跑批**永远停在"处理中"**，结论消息永远不来。
`initialMailHandled` 这个 ref 活过了 StrictMode 的二次挂载，但 timer 没有：第一遍排了 timer、
cleanup 清掉、第二遍因为 ref 已是 true 直接返回，再没人排。**跟今天第一件（updater 里放副作用）
是同一类错误**——把不该跨重挂载存活的东西交给了 ref。改成按消息 id 幂等、timer 每次重排。

## 八、一个查完发现不是 bug 的 bug

用户报"版本切换下拉不显示、被遮罩"。

第一次量到 `opacity: 0`，差点当成 bug 修——其实是**浏览器面板隐藏时 CSS 动画冻在第 0 帧**
（`bioazMenuIn` 卡在 `currentTime: 0`）。强制 `getAnimations().forEach(a => a.finish())` 之后
opacity 是 1。

然后怀疑是 `.mobileSidebarBackdrop` 全屏遮罩，也复现了——但挂探针验证发现**这个浏览器的
resize 根本不派发 `resize` / `matchMedia change` 事件**，所以侧边栏没像真实浏览器那样自动收起。
真实浏览器新开页面在 1010px 下是 `collapsed: true`、遮罩 `display: none`。**我复现的是我的工具，
不是产品。**

1600 / 1280 / 1100 / 1010 四档、普通与 Canvas 两种布局都测了，`elementFromPoint` 每个点命中的
都是菜单本身。最后只把**那一类** bug 的根源堵了：`.topbar` 有 `backdrop-filter`（自成层叠上下文）
却是 `position: static`，整棵子树会被压在任何 `position: relative` 的兄弟下面。

**结论：没修那个 bug，因为没找到它。** 需要用户复现时的窗口宽度 + 侧边栏是否展开。
