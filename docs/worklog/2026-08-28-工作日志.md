  **后果常驻，原因藏着**。

  首屏这四张说的是「这个工作台能做什么」，是能力清单。已改回四张全列。

### 二、退回返工这一屏（全天）

按老师和你的反馈，模型改了三次：

1. **删掉「逐条采纳」方案卡**——那是让数字同事替人做决定，改动绕过了参数收集，
   而且人对着的是它的转述不是审批人原话。它现在只做三件事：读、说清楚、把原件摊开。
2. **批注列表改回纯说明书**，上面没有任何动作按钮。改这件事只有一条路：
   右侧参数收集里人自己点。在批注上再放一颗「去改」，等于给了第二条路径。
3. **布局照 QA 审核台**：中间画布（报价单 + 批注两栏）、右边 320px 面板、
   底部一颗药丸。我先做成了 panelFocus 铺满整屏，那会把「改」和「确认」
   一起赶走，而这一屏的活恰恰要三样同屏。

配套做的：

- 要当场做的卡**跟着输入框走**——composer 缩成药丸，卡落到药丸上方；
  画布收起，卡回到 composer 上方。药丸也补了 chips 和「有 chips 即可发」。
- 发送那一下自动收画布。这是读与改的分界，由用户自己的动作触发。
- 画布进出给了过渡（进场从下方长出、收起时对话用更短的时长回来）。

## 翻出来的 bug

按「不报错、只安静地错」排：

1. **产物卡不在消息流里**，照着 `stage === "generated"` 渲染在所有消息后面。
   生成完先交接，产物卡就跑到「已交接给林一一」下面——读起来像交接完才生成的。
   跟昨天那条 run 记录是同一个坑，我昨天没想到它还有第二处。
2. **退回这件事本身在对话里没发生过**：「已交接给王林彬」紧接「已读取退回批注」，
   中间东西被退回来、附件跟着回来，一点痕迹都没有。新增 `inbound` 一类记录。
3. **run 记录标签撒谎**：退回刚进来那次记成「已更新报价参数」，那时什么都还没改。
4. **三条批注里两条改不了**（锚在 Discount 和 Bioanalysis 上，参数面板没格子）。
   演示要展示的正是「照批注在面板里改」，两条改不了当场就断。
5. **建议值不在选项表里**：批注说改成 10，采血点数只有 3/6/9，只能走「自定义」。
6. **药丸的发送键在有 chips 时仍然是灰的**——它死守 `!text.trim()`，
   而 composer 那边一直是「有 draftTabs 就能发」。
7. **版本从 v1 数起**：带着退回进来时被退回的那一版已经存在，它就是 v1。
8. 严格模式下 effect 跑两遍，ref 挡住第二遍、清理取消了第一遍的定时器，
   那段开场白永远不发生。
9. 容器查询**只能给容器的后代定样式**，`container-type` 挂错了层，两栏排不开。
