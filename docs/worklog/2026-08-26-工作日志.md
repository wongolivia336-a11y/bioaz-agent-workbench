### 二、站内信这一屏改了五轮

- **附件**：DMPK 报价从一个压缩包拆成两份真实产物（报价书 .docx + 计算表 .xlsx）。
  复核要同开两样对着看，打包只是逼人先解压。加了预览弹窗和下载；预览渲染的是
  审核画布里**同一份** `QuotePaper`（为此抽成共享组件）——预览若另画一版占位，
  看到的和点进去审的就不是同一张纸。
- **批注文案**：「此项不适用」→「不应计费」（原词只说状态不说处置，新词与
  「缺漏项」成对）；「不改不能过/仅提醒」→「必须修订/建议修订」（前者是口语，
  且说的是审批人的情绪，而批注是要退回给撰写人的）。加了第六类「其他」，
  **不填分类名不让提交**——没名字的「其他」就是那个会烂掉的桶。
- **列表变成一张卡**：原来是三条横条浮在白底上，最后一行到分页之间 **401px 空洞**
  （那不是页面留白，是列表容器撑出来的）。合成一个面板后间隙为 0。
  列名必须放进滚动容器内 sticky——放在外面的话，列表一出滚动条行就比列名
  少 15.2px，永远对不齐。
- **筛选从"混着三把尺子"改成三轴**：状态下拉里原本混了归属（待我处理）、
  类型（仅通知）和真状态，而 select 只能取一个值，所以选「已驳回」会**悄悄**
  丢掉归属、看到所有人的单，「我的已驳回」根本表达不出来。现在类型轴吸收通知
  并按 `Notice.source` 拆成「数字同事知会 / 系统通知」；归属不做筛子——收件箱
  本来就只装到你手上的东西。
- **删掉「处理中」状态**：它从来没区别于 `open`（侧栏计数、可处置判断、状态筛选
  三处都当同一件事），那句"已接手的单直接进画布"的注释描述的逻辑早已不存在。
  接手改成记一条流转：**流转记录说发生过什么，状态说现在还欠着什么。**

### 三、源码治理

量完的结论：**问题不是没规范，是规范没有执行层。**
`docs/design-system.md` 写得很对，末尾却老实写着「不阻断 typecheck、build 或 CI」。

| | 实测 |
|---|---|
| CSS 占比 | 22,000 / 41,761 行 = 53% |
| 全局样式表 | 23 个，平铺进同一个级联 |
| 重复选择器 | 595（其中 **193 跨文件**） |
| 疑似死类名 | 382 |
| 裸按钮类 vs `<Button>` | 53 处 vs **只有 5 个文件用** |

跨文件重复的根因是 `review.css` / `iteration.css` 这两个「新建文件追加修补」堆出来的
后覆盖层（`.taskExampleGrid` 定义了 12 遍）。

做了三件：

1. **`npm run audit:ui`** —— 跟 `scripts/audit-ui.baseline.json` 比，变差就报。
   散文会被跳过，数字不会。
2. **`Dialog` 补层栈 + `className`** —— 它原来自己写 keydown，漏了层栈（弹窗里
   再开弹窗，一次 Esc 掀两层）。`className` 是为了堵住那条产生 5 个手写弹窗的
   路：大家复制整份 markup，往往只是因为要调个宽度。本周写的两个弹窗已迁过去，
   计算值逐项一致。
3. **`.claude/skills/bioaz-workbench/SKILL.md`** —— 项目自己的技能（原来那目录里
   全是通用技能）。装 CSS 陷阱、验证方法、工具事故。
