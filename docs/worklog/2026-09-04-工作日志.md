## 两个回归，都是「昨天那笔改动的另一面」

### 一、表单收起时点铅笔，什么都不出现

昨天给参数表单加了常驻开关（`paramsOpen`），解决的是「参数填完就没有入口回头改」。
但右栏铅笔那条路只设了 `editingFieldId`，**卡片渲不渲染由 `paramsOpen` 说了算**。

于是：把表单收起来 → 点右栏铅笔 → 对话里回一句「请在下方选择一个新值」→
下方空空如也。

> 要人改，就得把要改的那一项摆到他面前。一句话的修法，但它是这条路上最糟的
> 一种坏法——**系统说了话，而说的事做不到**。

### 二、对话流不跟最新一条

`.dmpkChatScroller` 从头到尾没人动过 `scrollTop`。会话短的时候看不出来，
一旦超过一屏，**新消息全落在折叠线以下，而屏幕上什么都没变**。

实测：走到「生成报价单」那一步 `scrollHeight 1474 / 可视 816 / scrollTop 0`，
两张产物卡就在下面，人以为点了没反应。

**DMPK 同病**，所以修在共用层：`components/workbench-shell/useStickToBottom.ts`，
两条线各挂一行。

三个细节：

- **不是无条件滚到底。** 人往上翻是在看历史，这时候来条新消息把他拽回去，
  等于把他正在读的东西抽走。判据是「本来就贴在底部」（离底 ≤120px）。
- **要盯尺寸，不只盯消息数。** 每条回复左边那颗 logo 是异步加载的 `<img>`，
  它撑开高度的时候 React 早提交完了。只在消息变化时滚，实测差 233px。
  加 `ResizeObserver` 盯内容层。
- **先同步滚一次，再 rAF 补一次。** 见下面那条工具事故。

## 三个缺口

### 「不需要检测」不互斥

同时选中 IVIS 和「不需要检测」是一句自相矛盾的话。

**计价那边其实是对的**——`tumorPriceLines` 早就把「不需要检测」滤掉了，
金额一直准。但台账、chips、报价前预览、修改日志**四个地方**照原样显示
「IVIS Imaging、不需要检测」，客户看到的是一份自己打自己的参数表。

> **金额对不代表说法对。** 互斥只能在控件上挡。

做成了共用层的 `ParamField.exclusiveOptions`，两个方向都清：
选中「不需要检测」清掉其余，选中其余清掉「不需要检测」。只做一个方向的话，
「先勾 IVIS 再勾不需要检测」是干净的，反过来就留下一对矛盾的选中态——
**而人不会知道这两条路的结果不一样**。

`parseTumorRequest` 也守同一条规矩：「不需要检测，但要采个血」这种话客户会说，
两条规则会同时命中，而识别结果绕过控件直接进 fields。

### 序列化格式直接摆给人看

重复行落在 `value` 里是 `Vehicle:0.5% CMC-Na:0;G1:DrugA:10 mg/kg`。

台账、chips、修改日志、报价前预览、发出去的那句话——**五个地方读同一个 `value`**。
各写一套格式化必然分叉，所以只有一份 `formatParamValue(field, value)`：
非 repeat 原样返回（对 DMPK 是空操作），repeat 拆成 `A / B / C；D / E / F`。

### 修改日志从中途开始

昨天只在补全卡那条路上记了流水。于是首轮一句话认出来的六项参数**在日志里
毫无踪迹**——翻日志的人看到「模型」有值却查不到它是哪来的，只能猜。

三个入口统一走 `logChanges(before, after)`：一句话识别的、补全卡发的、
级联清空的。现在首轮就有 10 条。

## 工具事故：预览面板是隐藏页面

这一条值得单独记，**它伪装成「代码没生效」**，为它查了一轮 webpack chunk、
查了 StrictMode、查了 ref 指向。

预览面板默认 `document.visibilityState === "hidden"`，而隐藏页面
**不跑 `requestAnimationFrame`，也不投递 `ResizeObserver` 回调**。
我的自动滚底两者都用了，于是测出来「一动不动」，和没写这个 hook 一模一样。

判据一行：

```js
let f=0; requestAnimationFrame(()=>{f=1}); await new Promise(r=>setTimeout(r,900));
({visibility: document.visibilityState, rafFired: f})   // hidden / 0 就是它
```

两个结论，都写进 SKILL 了：

1. 验证前先 `tabs_select` 把面板亮出来；
2. 更重要的是——**别把正确性押在 rAF 上**。标签页在后台、窗口最小化都算隐藏，
   真实用户也会遇到。`useStickToBottom` 改成先同步滚一次、再 rAF 补一次。

顺带三条：

- **`computer` 的 `key: Return` 进不到 React 的 `onKeyDown`。** 回车没反应
  不代表产品坏了——用 `dispatchEvent(new KeyboardEvent(...))` 验，实测是好的。
- **右栏 tab 只认真实鼠标事件**（4px 拖拽阈值吞掉零距离合成点击）。
- **别在有循环引用的文件里用模块顶层常量读另一个模块的导出。**
  `inspectorPanels.tsx` ← `views.tsx` 这一对，顶层
  `const m = new Map(initialTumorFields.map(…))` 报过
  `ReferenceError: initialTumorFields is not defined`。改成函数。
