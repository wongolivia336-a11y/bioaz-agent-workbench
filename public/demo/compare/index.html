一页结论

三个差异点

01 · 架子

三列一样，名字随便叫

左任务、中对话、右面板，两边一个形状。「项目」还是「空间」只是叫法，能改。beta5 里我们借了一样：专家 Agent 按空间配置。它别的框架功能（工具页、记忆、知识）偏框架、不够实用，没有接。

02 · 右栏

一张固定卡 vs 面板容器

beta5 右栏是一张「参数收集 13/13」卡。我们把右栏做成固定位置的容器：面板模型 + tab 模型，可选搭配、可并列、可全屏、可收起。这是从 Codex / Claude Code 那种全自由面板收回来的——太自由，和业务不贴。

03 · 工作流与对话流

一条链在会话里走完

材料进来 → 识别、原文依据 → 参数卡按八维分页 → 右栏成账 → 改价补价 → 生成纸 → 交接 → 复核 → 退回 → 重出。beta5 停在追问参数和一张费用明细卡。这条链，是原型真正花功夫的地方。

3–9 页逐项对照；10 页起是报价线上的功能差异；第二部分是会议改动的细节。·
会话层

三列是同一套左任务、中对话、右面板——beta5 的会话页就是这个形状。差别只在右栏：一张固定的卡，还是一排能长的 tab。

beta5 · 会话

右栏一张「报价参数收集 13/13」卡，四组完成度；对话里参数靠打字，一段话二十项。形状跟我们一样，右栏是固定的。

原型 · 会话

同样三列；右栏是三个常驻 tab + 「+」（参数收集 / 报价板块 / 报价结果），中间对话流、参数卡、产物卡跟 beta5 同形。

一样的三列、对话流、右面板、产物卡。

还差在对话流：beta5 是「追问 11 项 → 用户打一段 → 费用卡」；我们是材料、参数、账、纸、交接一路走下去（第 7 页）。

设计点 · 右栏

固定位置的面板容器最早想学 Codex / Claude Code 那种自由面板，试了发现太灵活、跟业务不贴、门槛高。收回来：右栏位置固定，里面是可搭配的面板模型 + tab 模型——能加、能并列、能全屏、能收起。

为什么不做全自由Codex 那种想放哪放哪，用户得先学面板；业务要的是"报价时右边就该有这几样"。位置固定、内容可选，门槛最低。
面板模型 / tab 模型常驻的几个是模块登记的，「+」里是备选的；一个 tab 能拖成一列、能铺满、能收起，状态跟会话走。
对 beta5它那张固定卡，在这个模型里就是一个常驻 tab；其余的（来源、明细、产物）它没有位置放。

小地方

设计上的巧思不是功能，是让人少学一步、少点一下、少猜一次的地方。beta5 里对应的位置基本是空的。

hover

动效只在该动的地方

专家卡 hover 从卡底长出介绍（做什么 / 几步 / 交出什么）；空间行 hover 出 ↗ 才进入口页；参数卡点卡头开合、点别处自动收——不弹、不抢。

语言

一个口径说到底

「仅本次报价，价目表不动」「影响 X 行；合计 A → B」「原文为 X，已改为 Y」——对话、右栏、纸面三处一句话，人不用翻译。

风格

一套令牌管所有线

圆角、字号、时长、颜色都是令牌；参数卡那套类名两条报价线共用；跑一遍 audit 就知道哪儿走样。四条业务线看起来是一家的。

图标

右上角两颗，各管一件事

「总结对话」把会话钉成四段话，交接卡直接预填；「面板开关」收起右栏回两列。会话顶栏只放这两个，别的都在 tab 里。

这些都是迭代里改出来的，不是第一版就有的。·
